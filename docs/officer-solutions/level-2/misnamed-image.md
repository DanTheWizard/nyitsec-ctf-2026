# Hidden in Plain Sight — Challenge Author Notes

**Module:** `level-2` | **Challenge ID:** `misnamed-image` | **Difficulty:** Easy

## Learning goal

Students must investigate a file's **content type**, rather than trust its `.txt` extension. The attachment is a **real PNG image**, misnamed `notice.txt`. The visual phrase in the picture is the case-sensitive answer. The student's pwn.college flag is generated by the platform and revealed only after correct verification.

This is a format-identification task, not steganography or encryption. Do not accidentally add the readable answer to `DESCRIPTION.md` or a second plaintext input file.

## Files

- `notice.txt`: valid PNG image data with a misleading `.txt` extension.
- `.init`, `.workspace.py`, `.ctfignore`: standard NYITSec staging. Only `notice.txt` is copied into the student's writable `/nyitsec-ctf` workspace.
- `verify`: standard privileged Python checker comparing a SHA-256 digest; it only reads `/flag` after a correct answer.
- `bin/nyitsec-answer`: regular PATH shortcut to protected `/challenge/verify`.

## Safe manual solution test

1. Start the challenge. Confirm `pwd` is `/nyitsec-ctf` and `ls -la` shows `notice.txt`.
2. Run `file notice.txt` and confirm it reports PNG image data.
3. Run `cp notice.txt notice.png`; inspect `notice.png` in **Workspace → Desktop** or **Workspace → Code (VS Code)**.
4. If Code does not open the project automatically, use **File → Open Folder → /nyitsec-ctf**.
5. Enter an incorrect phrase through `nyitsec-answer` and confirm no flag is revealed. Enter the pictured phrase exactly and confirm the platform-generated flag appears and submits successfully.
6. Check that the original five Fundamentals challenges remain untouched.

## Desktop customization question

pwn.college runs an XFCE desktop with its own background image (configured globally by pwn.college). Modifying the user's home `~/.config/xfce4` or the code-server last-opened workspace could persist into unrelated dojos, so **this challenge does not change either default**. A challenge-scoped customization should be separately tested before changing the shared environment.

## Flag handling

The image phrase is a *synthetic challenge answer*, not a real secret or pwn.college flag. The checker stores a SHA-256 digest rather than readable answer text and requires the full case-sensitive phrase with its symbol. Never hardcode real or reusable platform flags.

## Officer QA: verified answer and repeatable solution

**Exact correct answer:** `ThePassword#LOL`  
**Deliberately incorrect input:** `ThePassword#LOLx`  
**Input policy:** Case-sensitive, including `#`; leading/trailing whitespace is stripped.

### Reproduce the intended solution

Check the misleading extension and open the PNG under its correct name:

```bash
cd /nyitsec-ctf
file notice.txt
cp notice.txt notice.png
```

Open `notice.png` with the pwn.college Desktop image viewer or VS Code. The image pixels display `ThePassword#LOL`. This should remain a *visual* solution, not plaintext embedded into student descriptions.

### Noninteractive checker test over SSH

The following commands inspect only whether the checker prints its success marker. They do **not** print or store the student's unique pwn.college flag.

```bash
if printf '%s\n' 'ThePassword#LOLx' | nyitsec-answer | grep -Fq 'Correct!'; then
  echo 'FAIL: incorrect input accepted'
else
  echo 'PASS: incorrect input rejected'
fi
if printf '%s\n' 'ThePassword#LOL' | nyitsec-answer | grep -Fq 'Correct!'; then
  echo 'PASS: known correct input accepted'
else
  echo 'FAIL: known correct input rejected'
fi
```

These are officer-only synthetic answers, not pwn.college flags. Do not add them to student-facing descriptions or record actual flag values in QA reports.
